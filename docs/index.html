Why this, and not HTML→PDF?

Most "HTML to PDF" tools drive a headless browser and screenshot the page — the result is an image, text is not selectable, and pagination is an afterthought. pdf-report-engine lays out, line-breaks, paginates and embeds glyphs in-process, emitting true vector text. It is built for reports: repeated column headers, group breaks, subtotals, running page numbers, and band-based page headers/footers.

Features

Vector, selectable text

Fonts embed as /Type0 → /CIDFontType2 composites with a /ToUnicode CMap, so text extracts cleanly — including CJK.

Band pagination

Jasper-style bands: title, pageHeader, detail, groupHeader/Footer, pageFooter, summary, plus a translucent background band for letterheads and watermarks.

Repeated headers & groups

Table column headers repeat on every page; groups carry subtotal footers with keep rules and widow/orphan control.

Running tokens

{PAGE} / {TOTAL} / {TOP} resolved per page inside bands.

Two authoring modes

Hand-build the ReportDoc IR in JS, or feed an HTML subset through htmlToReportDoc().

Vector charts

Bar, line, area, pie and donut — stacked series, legends, value axes and number formats, authored as IR blocks or declarative data-chart elements.

Bookmarks, TOC & links

Headings build a nested PDF outline; a toc block adds dot leaders with real page numbers, and text links to URLs or #anchors.

QR & barcodes

qr, code128 and ean13 blocks encode literal values or bound data — vector modules, quiet zones and optional human-readable text.

Stylesheets & highlights

A real <style> subset: tag, class, id and compound selectors with CSS specificity, descendant/child combinators, plus <mark> run highlights.

Merged cells

Horizontal colSpan and vertical rowSpan merges, including combinations in one grid.

Images — offline & online

Local paths, data: URIs, raw bytes, and http(s) URLs — with aspect-ratio sizing, alignment and borders.

Sandboxed expressions

Data bindings evaluate inside a Proxy-whitelisted scope — no raw eval of globals.

Measure == render

Text widths are measured through the exact code path pdfkit paints with, so wrapped lines never overflow their box.

See them together: samples/dashboard.html is a single report with stylesheet selectors, a translucent watermark, a clickable TOC, bar/donut/area charts, QR / Code 128 / EAN-13 codes, highlights and internal links.

How it works

Two entry points funnel through one pipeline:

authoring (IR or HTML)  →  ReportDoc IR  →  layout  →  pagination  →  pdfkit writer  →  PDF bytes
  • renderToBuffer(report, options?) — one-shot: IR in, PDF bytes out.
  • createReport(report, options?) — the live pdfkit doc plus the paginated pages model, so you can stream yourself.

60-second taste

import fs from 'node:fs';
import { renderToBuffer } from 'pdf-report-engine';

const report = {
  info: { title: 'Hello, PDF' },
  page: { size: 'a4', margin: 56 },
  style: { fontFamily: 'Helvetica', fontSize: 11 },
  body: [
    { type: 'heading', level: 1, content: 'Quarterly Snapshot' },
    { type: 'paragraph', content: 'Built entirely in JavaScript — no browser.' },
  ],
};

const pdf = await renderToBuffer(report);
fs.writeFileSync('report.pdf', pdf);
