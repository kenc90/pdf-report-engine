CSS subset

Every <style> element is parsed once into flat rules. Supported selectors: tag, *, class, id and compound combinations, comma lists, and descendant (whitespace) / child (>) combinators. 

h2 { color: #0f2f57; }
.kpi { background-color: #eef4ff; }      /* class */
#note { background-color: #fff6cc; }     /* id */
.kpi strong { color: #b23a2f; }          /* descendant */
section > h2 { letter-spacing: 0.3pt; }  /* child */
h1, h2 { margin-bottom: 4pt; }           /* list */

Specificity is ids × 10000 + classes × 100 + tags, source order breaks ties, then the styles class map applies, and inline style wins over both. At-rules are skipped by the cascade (@page and @font-face have their own parsers); pseudo-class and attribute selectors are ignored.

bar/line/area map one value per category per series; pie/donut read series[0].values and label slices from categories. If legend is omitted it defaults to right for pie/donut, bottom for multiple series and none for a single series. A chart is one atomic fragment, so it never splits across pages.

The default increase/decrease/total colours can be overridden with waterfallColors.

The codes are drawn as vector rectangles; nothing is rasterised. EAN-13 accepts 12 digits (the check digit is appended) or 13 (the check digit is validated). Invalid values throw at layout time.

Heading outline

Headings emit outline entries by default, nested by level. Re-level or number an entry with outline, or opt a single heading out: 

{ type: 'heading', level: 2, content: 'Scope',
  outline: { level: 1, numbering: 'append' } }   // "1.1 Scope" in the bookmark tree
{ type: 'heading', level: 3, content: 'Detail', outline: false }

ReportDoc.outline: false suppresses the bookmark tree for the whole document; a toc block still renders its entries.

Content & bindings

A Content is a string, number, span, or an array of them. Spans bind to data:

'Revenue'                                  // literal
{ bind: 'amount', format: '#,##0.00' }     // field + number format
['Page ', { bind: '$page.number' }]         // mixed array
{ bind: "concat('Total: ', money($vars.grandTotal))" }  // sandboxed expression

{ text: 'appendix', link: '#appendix' }     // internal jump (any block id)
{ text: 'live report', link: 'https://example.com/report' }  // external URI
{ text: 'note', style: { backgroundColor: '#fff2a8', opacity: 0.9 } }

Links are clipped to the run's text, not the whole line, and #anchor targets resolve against any block or heading carrying that id. Run backgroundColor paints behind the glyphs; run opacity fades that fill and the text.

Expression language

Bindings, data sources, group keys and chart series all speak the same tiny language. Every example below is asserted by test/expr.test.ts, so the output column is what the engine really prints.

Two forms

FormWritten asHow it resolves
Field path 'amount', '$row.amount', '$data.company', '$row.items[0].sku', 'customer.city' No code is generated. The current row is tried first, then the report data root. The leading $ is optional, so '$amount' reads as “row field, else data field”.
Expression '$row.qty >= 3 ? "bulk" : "standard"', "concat('Total: ', money($vars.grandTotal))" Anything with an operator, a ternary or a call. Compiled once per distinct source and reused for every row. Bare field names are not in scope: 'amount * 2' throws amount is not defined — write '$row.amount * 2'.

Both forms are accepted wherever Content or Expr appear: ContentSpan.bind, dataSource ({ bind } or { each, of }), groups[].by/label, info.title, chart categories and series[].values, and the HTML adapter’s data-bind / data-each / data-format.

visible is the exception: only the literal false hides a block. visible: { expr: '$row.flag' } type-checks but is ignored today — filter the IR before rendering, or bind the content conditionally.

Grammar

Literals (numbers, 'strings', "strings", template literals, booleans, null, arrays and object literals), member and index access, ?., ??, arithmetic (+ - * / % **), comparison, logical && || !, ternary ? :, calls of library functions — and calls on values you already hold, such as $row.region.toUpperCase() or $row.items.map(x => x.sku). There are no statements, no assignment, no new, and no this.

Row aggregates. sum, min and max in the library are plain numeric helpers over their arguments (arrays are flattened) — they cannot see the row set, because an expression is evaluated once per row. Row-set totals come from layout instead: money($group.amount_sum), $group.qty_count, $group.rowCount. For something ad hoc, read the array you already have: sum($data.rows.map(r => r.amount)). The rows parameter mentioned in some sources is reserved and always empty today.

Sandbox guards

A binding is compiled into a strict-mode function, but it is not given the host realm: every ECMAScript and Node global (eval, Function, Date, Math, JSON, Object, Array, Promise, process, require, fetch, …) is shadowed by a parameter bound to undefined, and the closure is invoked detached so this is undefined. Prototype plumbing is rejected at compile time — constructor, prototype, __proto__ and any dunder name, in every access form (.constructor and ['constructor'] included), plus this, arguments, globalThis, process, require, import, export and module as free identifiers. Incoming data is walked and those keys are stripped before evaluation, so a hostile JSON payload cannot be used as a stepping stone. 

throw new Error(...)   // rejected: forbidden identifier
$row.region.constructor.constructor('return 6*7')()   // rejected: constructor
Date.now()             // Date is undefined here — use now() / date()
Math.PI                // Math is undefined — there is no pi; use a $vars entry
JSON.stringify($row)   // JSON is undefined
Because the check is a source scan, those words are also unavailable inside string literals — concat('read the ', $row.note) is fine, but a literal that says 'process' or 'constructor' is refused. Treat a report template as an input you author, not as an untrusted interpreter: the guards make accidents expensive to hit, they are not a OS-level jail.

Number patterns

A pattern is the ICU/Java shape used by format, money, number, percent and every format field on a span, cell or chart axis.

TokenMeaning
0digit, padded with a zero when absent (0000 + 42 → 0042).
#digit, left blank when absent (#,##0.### + 1.5 → 1.5, not 1.500).
. ,decimal separator and grouping separator (grouping is dropped if it sits in the fraction). Rounded half away from zero: #,##0 + 1234.5 → 1,235, 1234.4 → 1,234.
% ‰multiply by 100 / 1000. The scale applies wherever the sign sits, but a leading one stays a prefix: #,##0% + 0.1234 → 12%, %#,##0.0 → %12.3.
¤currency symbol from the active symbols table ($ by default); a literal $ in the pattern works too, and the negative sign is printed before it: -$52.00.
Eexponential notation — the digits after E set the minimum exponent length: 0.###E0 + 123456 → 1.235E5.
'text' "text" ''quoted literals: '€'#,##0.00 → €12.50; a quoted "%" is text, not a scale.
*cpad character: *0#,##0 + 42 → 0042.
;section separator, in the order positive; negative; zero; text.
[Red]parsed into a colour for the section (see the note below).
- ( ) spaceordinary literal affixes, so a section can be a label only: #,##0;(#,##0);"-" prints - for zero.
 
formatNumber(1234.5, '#,##0.00')                 // 1,234.50
formatNumber(1.5, '#,##0.###')                    // 1.5
formatNumber(42, '0000')                          // 0042
formatNumber(-52, '$#,##0.00')                    // -$52.00
formatNumber(-52, '$#,##0.00;[Red]-$#,##0.00')    // -$52.00   (see the colour note)
formatNumber(0.1234, '#,##0%')                    // 12%
formatNumber(0.1234, '#,##0.0‰')                  // 123.4‰
formatNumber(123456, '0.###E0')                   // 1.235E5
formatNumber(12.5, "'€'#,##0.00")                 // €12.50
formatNumber(42, '*0#,##0')                       // 0042
formatNumber(0, '#,##0;-#,##0;(0);@')             // (0)
formatNumber(NaN, '#,##0.00')                     // NaN
formatNumber(Infinity, '#,##0.00')                // ∞
Non-finite values never take a numeric section: NaN prints NaN and ±Infinity prints ∞, so a bad binding shows up as a token rather than pattern-shaped noise. A [Red]-style colour section is recognised by the parser but its colour is not applied today — only the text is used. Paint a negative red by choosing the span style yourself (a format + style pair, or an iif(...) in HTML).

Input may be a Date, a parseable string or an epoch number. Unknown tokens are passed through unchanged rather than guessed, and there is no support for quarters, week-of-year, eras or timezone offsets (QQQQ prints QQQQ). Names are English only.

A pattern is read as numeric if it contains 0, #, % or ‰; anything else goes to the date formatter — which is why format(value, 'dd/MM/yyyy') and format(value, '#,##0.00') share one entry point.

Style & box properties

Every block carries two bags: StyleProps, which inherits down the node tree, and BoxProps (its superset), which sizes one box and does not inherit. Both are sparse — a property left undefined keeps the parent's value — and layout collapses them into a dense ResolvedStyle per node, so setting a family and size once on ReportDoc.style and overriding one cell is normal.

Lengths and colours

A Length is a number — always points — or a string with a unit: pt, mm, cm, in, pc (12pt) and px (the CSS 96dpi reference pixel, ×0.75). % is not resolved against a container; it is read as points, so prefer explicit sizes or leave a column unpinned and use grow. Internal coordinates are points end to end: layout never sees DPI.

A ColorInput is [r,g,b] in 0…1 or a string: #rgb, #rrggbb (with optional alpha, ignored for painting), rgb() / rgba() in 0–255, 0–1 or percent forms, or a name from a fixed ~50-entry list (crimson, steelblue, lightgray…). Anything else throws at layout time; note that transparent resolves to white, not to “no paint”.

What the HTML adapter understands

Declarations are parsed from <style> sheets, class matches and inline style attributes, ordered by CSS-ish specificity (ids × 10000 + classes × 100 + tags, source order breaking ties), with inline styles last. A trailing !important is simply removed from the value, so specificity and source order alone decide which declaration wins.

Pagination model

Rendering runs in three passes: measure fixed bands against a placeholder, flow the body with break/keep rules and repeated headers, then re-flow the bands with the real $page so running tokens are correct. Layout never touches pdfkit, and the writer translates fragment-local coordinates into absolute page space.

Charts, barcodes and TOC rows are atomic fragments. Every heading contributes an outline entry, and every block id a named destination; the writer registers both page-by-page before painting. When the body contains a toc block, createReport wraps pagination in a fixed-point loop (at most four passes) so the entries and their page numbers are stable.
