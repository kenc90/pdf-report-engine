Runnable examples

The repo ships five plain .mjs scripts under examples/ that consume the package exactly like a JS caller (import … from 'pdf-report-engine'). Build once, then run any file — each writes a PDF to output/examples/, needs no fonts and no network. 

npm run build
node examples/01-basic.mjs
node examples/02-data-table.mjs
node examples/03-from-html.mjs
node examples/04-create-report-stream.mjs
node examples/05-images.mjs
FileShowsEntry point
01-basic.mjsMinimal IR: heading, paragraph, static tablerenderToBuffer
02-data-table.mjsdataSource, grouping, subtotals, running footer, summaryrenderToBuffer

One-document tour: samples/dashboard.html

The quickest way to see everything at once is the dashboard sample. It uses a <style> sheet with tag/class/id/descendant/child selectors, a translucent background band, a clickable TOC with real page numbers, bar / stacked bar / line / area / pie / donut charts, QR / Code 128 / EAN-13 codes, <mark> highlights, external and #anchor links, and a nested PDF outline. The dedicated rich-cell, conditional-formatting and chart-depth samples below push each newer feature to its limit. 

npm run html:pdf -- samples/dashboard.html -o output/

The sections below break the same features down into standalone snippets; the five .mjs scripts above stay focused on the core data/report flow.

Streaming with createReport

The lower-level, synchronous entry returns the pdfkit doc and the paginated pages array, so you can pipe the bytes to any writable stream.

import fs from 'node:fs';
import { createReport } from 'pdf-report-engine';

const { doc, pages } = createReport(report);
console.log('paginated into', pages.length, 'page(s)');

const out = fs.createWriteStream('output/stream.pdf');
doc.pipe(out);
doc.end();

Online images via a custom loader

Point src at an http(s) URL and either let the built-in fetch run, or inject a resolveImage hook (proxy / auth / cache / test fixtures).

const report = {
  body: [{ type: 'image', src: 'https://cdn.example.com/chart.png', width: 200, align: 'center' }],
};

const pdf = await renderToBuffer(report, {
  images: {
    resolveImage: async (url) => {
      const res = await fetch(url);
      return new Uint8Array(await res.arrayBuffer());
    },
    timeoutMs: 10000,
    onError: 'throw',
  },
});

Merged cells (colSpan / rowSpan)

Horizontal and vertical merges work in both the IR and the HTML subset. Author them on cells; the engine lays the run out as a single grid fragment so borders and fills line up.

// IR: a banner cell spanning three columns
{
  type: 'table',
  columns: [{ grow: 1 }, { grow: 1 }, { grow: 1 }],
  staticRows: [
    { cells: [{ content: 'Region summary', colSpan: 3,
                align: 'center', backgroundColor: '#dce6f2', style: { fontWeight: 'bold' } }] },
    { cells: [{ content: 'North' }, { content: 'Q1' }, { content: '$1,000' }] },
    { cells: [{ content: '2026', rowSpan: 2 }, { content: 'Jan' }, { content: '$400' }] },
    { cells: [                       { content: 'Feb' }, { content: '$600' }] },
  ],
}

In HTML it is just the familiar attributes:

<table>
  <tr><th colspan="3">Region summary</th></tr>
  <tr><td rowspan="2">2026</td><td>Jan</td><td>$400</td></tr>
  <tr><td>Feb</td><td>$600</td></tr>
</table>

Rich table cells

A cell can hold any flow block, not just text. Give it blocks and the table lays the stack out inside the padded cell box — images, QR/barcodes, charts, nested tables and paragraphs all work. The row grows to the tallest cell and stays atomic for pagination, so a row never splits. 

{
  type: 'table',
  columns: [{ grow: 2 }, { width: 70 }, { width: 90 }],
  staticRows: [{
    cells: [
      // a small text stack
      { blocks: [
        { type: 'paragraph', content: 'Northwind Retail', style: { fontWeight: 'bold' } },
        { type: 'paragraph', content: 'Enterprise · EMEA', style: { fontSize: 8, color: '#94a3b8' } },
      ] },
      // an image, centred inside its cell
      { align: 'center',
        blocks: [{ type: 'image', src: 'assets/logo.png', width: 26, height: 26 }] },
      // a QR code
      { align: 'center',
        blocks: [{ type: 'barcode', symbology: 'qr', value: 'NW-001', moduleSize: 1.2 }] },
    ],
  }],
}

In the IR, a cell with no content lays out its blocks as a stack; when both are set, content wins. In HTML the stack is simply the <td>'s own block-level children: 

<td style="padding:6pt">
  <img src="assets/logo.png" style="width:26pt; height:26pt">
  <p><strong>Northwind Retail</strong><br>Enterprise · EMEA</p>
  <div data-barcode="qr" data-value="NW-001"></div>
  <div data-chart="bar" data-values="4,6,5,8" data-grid-lines="false"
       style="height:40pt"></div>
</td>

Inline children are wrapped into a synthetic paragraph, so mixed content still flows. A data-bind on the same cell wins over its block children. See samples/rich-cells.html for a full table of images, QR/EAN codes and sparklines.

Conditional formatting

Three primitives cover most conditional output: visible drops a block, row or cell; styleWhen applies a style while an expression is true; and colorScale paints a cell background by interpolating its number between two colours (each cell gets one flat fill, and dark fills switch their text to white). All expressions run in the normal sandboxed scope, so they can read $row, $index, $group and $data. 

{
  type: 'table',
  dataSource: { bind: '$data.rows' },
  columns: [
    { key: 'account', grow: 2 },
    // Heatmap: min/max omitted -> the range comes from this column's data.
    // Text flips to white automatically on dark fills.
    { key: 'revenue', width: 110, align: 'right',
      colorScale: { from: '#eef4ff', to: '#1e3a8a' } },
    { key: 'margin', width: 80, align: 'right',
      colorScale: { min: 0, max: 60, from: '#fee2e2', to: '#15803d' } },
  ],
  detail: {
    visible: { expr: '!$row.void' },          // hide a row entirely
    styleWhen: [
      { when: '$row.margin < 10', style: { backgroundColor: '#fff5f5' } },
    ],
    cells: [
      { bind: 'account' },
      { bind: 'revenue', format: '#,##0' },
      { bind: 'margin', format: '0.0"%"',
        styleWhen: [
          { when: '$row.margin < 10', style: { color: '#b91c1c', fontWeight: 'bold' } },
        ] },
    ],
  },
}

Sibling atoms follow the same rules: a column can carry the scale, a row or a cell can carry its own visible and styleWhen, and the scale can be declared on a cell too. HTML spells the same three features as attributes:

<table data-each="row in $data.accounts">
  <tr data-when="$row.growth < 0" data-when-style="background-color: #fff5f5">
    <td data-bind="$row.account"></td>
    <td data-bind="$row.revenue" data-format="#,##0"
        data-color-scale="from=#eef4ff; to=#1e3a8a"></td>
    <td data-bind="$row.margin" data-when="$row.margin < 10"
        data-when-style="color: #b91c1c; font-weight: bold"></td>
  </tr>
</table>

<!-- data-if hides any block, row or cell -->
<p data-if="$data.accounts.length === 0">No positions this period.</p>

data-color-scale takes semicolon-separated min=, max=, from=, to= and text= pairs. Omitted bounds are derived per column across the whole table, not per page. See samples/conditional-format.html (with conditional-format.data.json) for row filtering, row highlights and two heatmaps, and samples/color-scale.html for the ramp itself, explicit vs automatic domains and the text=false behaviour.

Page bands & running tokens (IR)

Bands repeat on every page; {PAGE}/{TOTAL} (or $page.number/ $page.total in expressions) resolve per page only inside bands.

bands: {
  pageHeader: { height: 34, blocks: [{ type: 'heading', level: 1, content: 'Quarterly Report' }] },
  pageFooter: {
    style: { fontSize: 8, color: '#666' },
    blocks: [{ type: 'paragraph', align: 'right',
      content: ['Page ', { bind: '$page.number' }, ' of ', { bind: '$page.total' }] }],
  },
}

Page bands in HTML (data-band)

The same bands authored in markup: tag any block-level element with data-band="…" and the adapter lifts it out of the body flow into a repeated page band. Supported types: title, pageHeader, pageFooter, summary, background. An height on the element fixes the band height; running tokens are written inline as {PAGE} / {TOTAL}. 

<header data-band="pageHeader" style="height:34pt; border-bottom:1px solid #dbe2ea">
  <h1 style="font-size:16pt; color:#1a3d6d">Quarterly Report</h1>
</header>

<footer data-band="pageFooter" style="height:20pt; font-size:8pt; color:#666">
  <table>
    <tr>
      <td style="width:300pt">pdf-report-engine</td>
      <td style="text-align:right">Page {PAGE} of {TOTAL}</td>
    </tr>
  </table>
</footer>

<section data-band="title">
  <h1>Annual Summary</h1>
  <p>Shown once at the top of the first page.</p>
</section>

<section data-band="summary" style="font-weight:bold">
  Grand total: $1,240,000
</section>

<!-- Normal body flow, repeating under the pageHeader / above the pageFooter -->
<p>Body content …</p>

Feed it through the adapter and render exactly like any other document — the bands repeat on every page and {PAGE}/{TOTAL} resolve per page: 

const report = htmlToReportDoc(html, { baseDir: 'samples' });
const pdf = await renderToBuffer(report);

The repo's samples/ folder has runnable versions — image.html and annual-report.html use data-band headers/footers.

Images in HTML (<img>)

A block-level <img> is embedded as a real PDF image object. Its src may be a local path, a data: URI, or an http(s) URL (the CLI/adapter fetches remote URLs at render time). Relative paths resolve against baseDir (the CLI uses the HTML file's folder). Give width/height as attributes or in style; supply just one and the engine keeps the intrinsic aspect ratio. 

<!-- natural size, shrunk to fit the page -->
<img src="assets/logo.png" alt="Logo">

<!-- width only: height follows the aspect ratio -->
<img src="assets/logo.png" width="240">

<!-- alignment is the image's OWN text-align (it is a block) -->
<img src="assets/logo.png" width="160" style="text-align:center">

<!-- explicit box + a ruled frame -->
<img src="https://cdn.example.com/chart.png" width="220" height="80"
     style="border:1px solid #b8c4d4; padding:4pt">

Images also work inside repeated bands — a letterhead logo in a page header:

<header data-band="pageHeader" style="height:40pt; border-bottom:1px solid #dbe2ea">
  <img src="assets/logo.png" width="80" style="text-align:right">
</header>

Images are block-level only — place <img> as its own element, not inline inside a paragraph or a table cell. See samples/image.html (local) and samples/image-online.html (remote) for runnable versions.

Charts (IR and HTML)

Charts are ordinary blocks: choose a kind, give it categories and one or more series, and the engine emits vector marks as a single atomic fragment. Here is a grouped bar chart, a line chart with an explicit value axis, and a donut (pie is the same block without innerRadius): 

{
  type: 'chart', kind: 'bar', title: 'Revenue vs. cost ($M)', height: 170,
  categories: ['Q1', 'Q2', 'Q3', 'Q4'],
  series: [
    { name: 'Revenue', values: [12.4, 18.1, 15.2, 22.6] },
    { name: 'Cost',    values: [7.1, 9.4, 8.2, 11.3] },
  ],
  legend: 'bottom', showValues: true,
  valueAxis: { format: '#,##0.0', ticks: 5 },
}

{
  type: 'chart', kind: 'line', title: 'ARPU ($)', height: 160,
  categories: ['Jul', 'Aug', 'Sep', 'Oct'],
  series: [
    { name: 'Consumer',   values: [21.4, 22.0, 23.1, 24.3] },
    { name: 'Enterprise', values: [38.2, 39.6, 39.1, 43.0] },
  ],
  // bar/area force the axis through zero; line does not, so trends keep their shape.
  valueAxis: { min: 18, max: 48, ticks: 4, format: '$#,##0.0' },
}

{
  type: 'chart', kind: 'donut', title: 'Revenue mix', height: 150,
  categories: ['North', 'South', 'East', 'West'],
  series: [{ values: [42, 28, 18, 12] }],   // pie/donut read series[0]
  legend: 'right', innerRadius: 0.55,
}

In HTML, one element declares a chart. A <table data-chart> is plotted from its own rows instead — the header row names the series and the first column names the categories — so a table you already render can be shown as a chart: 

<div data-chart="bar" data-title="Revenue vs. cost ($M)"
     data-categories="Q1,Q2,Q3,Q4"
     data-series="Revenue:12.4,18.1,15.2,22.6; Cost:7.1,9.4,8.2,11.3"
     data-legend="bottom" data-show-values="true"
     data-value-format="#,##0.0" style="height:170pt"></div>

<div data-chart="bar" data-title="Revenue by region (stacked)"
     data-categories="Q1,Q2,Q3,Q4"
     data-series="North:5.2,6.1,6.8,7.4; South:3.1,3.4,3.9,4.2"
     data-stacked="true" data-legend="bottom" style="height:160pt"></div>

<div data-chart="donut" data-title="Revenue mix"
     data-categories="North,South,East,West" data-values="42,28,18,12"
     data-legend="right" style="height:150pt"></div>

<table data-chart="area" data-title="Pipeline" data-stacked="true"
       data-colors="#2E5FA3,#E8833A" style="height:150pt">
  <thead><tr><th>Month</th><th>Actual</th><th>Plan</th></tr></thead>
  <tbody>
    <tr><td>Jul</td><td>10</td><td>12</td></tr>
    <tr><td>Aug</td><td>14</td><td>13</td></tr>
    <tr><td>Sep</td><td>19</td><td>15</td></tr>
  </tbody>
</table>

Three kinds go deeper. A combo gives each series its own mark type and axis, stacked: '100%' normalises every category to its own total, and a waterfall turns one delta series into a running balance: 

{
  type: 'chart', kind: 'combo', title: 'Revenue and margin', height: 180,
  categories: ['Q1', 'Q2', 'Q3', 'Q4'],
  series: [
    { name: 'Revenue', values: [12, 18, 15, 22] },
    { name: 'Margin', values: [18, 19, 21, 24], type: 'line', axis: 'right' },
  ],
  rightAxis: { min: 0, max: 30, ticks: 5, format: '0"%"' },
  legend: 'bottom',
}

{
  type: 'chart', kind: 'bar', stacked: '100%', title: 'Revenue mix', height: 160,
  categories: ['Q1', 'Q2', 'Q3'],
  series: [
    { name: 'Product', values: [60, 55, 50] },
    { name: 'Services', values: [40, 45, 50] },
  ],
  showValues: true,          // labels and axis read as percentages
}

{
  type: 'chart', kind: 'waterfall', title: 'Cash bridge', height: 180,
  categories: ['Opening', 'Revenue', 'Costs', 'Closing'],
  series: [{ name: 'Cash', values: [80, 30, -20, 0] }],
  totals: [0, 3],            // 0 seeds the opening balance, 3 draws the close
  waterfallColors: { increase: '#15803d', decrease: '#b91c1c', total: '#1e3a8a' },
  showValues: true,
}

The declarative equivalents add a handful of attributes:

<div data-chart="combo" data-title="Revenue and margin"
     data-categories="Q1,Q2,Q3,Q4"
     data-series="Revenue:12,18,15,22; Margin:18,19,21,24"
     data-series-types="bar,line" data-series-axes="left,right"
     data-right-min="0" data-right-max="30" data-right-format='0"%"'
     style="height:180pt"></div>

<div data-chart="bar" data-title="Revenue mix" data-stacked="100%"
     data-categories="Q1,Q2,Q3"
     data-series="Product:60,55,50; Services:40,45,50"
     data-show-values="true" style="height:160pt"></div>

<div data-chart="waterfall" data-title="Cash bridge"
     data-categories="Opening,Revenue,Costs,Closing" data-values="80,30,-20,0"
     data-totals="0,3" data-show-values="true"
     data-waterfall-colors="increase=#15803d; decrease=#b91c1c; total=#1e3a8a"
     style="height:180pt"></div>

Series values and categories also accept CSV strings ('12,18,9') or bindings ('$data.revenue'). See Getting started → Charts for the full attribute list, and samples/chart-depth.html for a runnable combo / 100% / waterfall page.

Bookmarks, TOC and links

Headings build the PDF outline automatically. Add ids so TOC rows and #anchor links have a destination, and insert a toc block where the contents should appear: 

const report = {
  body: [
    { type: 'heading', level: 1, id: 'intro', content: 'Quarterly report' },
    { type: 'toc', title: 'Contents', maxLevel: 2 },   // dot leaders + real page numbers

    { type: 'heading', level: 2, id: 'revenue', content: 'Revenue' },
    { type: 'paragraph', content: [
      'See the ', { text: 'online dashboard', link: 'https://example.com/dashboard' },
      ' or jump to ', { text: 'risk factors', link: '#risk' }, '.',
    ] },

    { type: 'heading', level: 2, id: 'risk', content: 'Risk factors' },
  ],
};

The same document in HTML:

<h1 id="intro">Quarterly report</h1>
<div data-toc data-title="Contents" data-level="2"></div>
<p>See the <a href="https://example.com/dashboard">online dashboard</a>
   or jump to <a href="#risk">risk factors</a>.</p>
<h2 id="risk">Risk factors</h2>

TOC page numbers come from a fixed-point pagination loop, so they stay correct even when adding an entry changes the TOC's own height. Suppress a single bookmark with outline: false on the heading, or the whole bookmark tree with report.outline = false — a toc block still renders its entries.

QR codes and barcodes

Three symbologies ship as vector blocks: QR, Code 128 and EAN-13. Values are ordinary Content, so a code can encode literal text or a bound field: 

/* QR: error correction and module size are optional */
{ type: 'barcode', symbology: 'qr',
  value: 'https://example.com/reports/2026-Q3',
  moduleSize: 2.2, errorCorrection: 'Q', quietZone: 4 }

/* Code 128: optional bar height and human-readable caption */
{ type: 'barcode', symbology: 'code128', value: 'RPT-2026-Q3-0042',
  height: 36, showText: true }

/* EAN-13: 12 digits (checksum appended) or 13 digits (checksum validated) */
{ type: 'barcode', symbology: 'ean13', value: '590123412345' }

/* Data-driven: the encoded value resolves against the report scope */
{ type: 'barcode', symbology: 'qr', value: { bind: '$data.order.trackingUrl' } }

And the declarative form:

<div data-barcode="qr" data-value="https://example.com/reports/2026-Q3"
     data-module-size="2.2" data-error-correction="Q"></div>
<div data-barcode="code128" data-value="RPT-2026-Q3-0042"
     data-color="#0f2f57" style="height:36pt"></div>
<div data-barcode="ean13" data-value="590123412345"></div>

<!-- bound from data, with alignment -->
<div data-barcode="qr" data-bind="$data.order.trackingUrl"
     style="text-align:center"></div>

A QR code is square and ignores showText; 1D codes print their value below the bars unless showText: false / data-show-text="false". Invalid values (non-digits for EAN-13, unsupported Code 128 input) throw at layout time instead of producing a bad scan.

Stylesheets, classes and inline highlights

The HTML adapter parses <style> into a small cascade with CSS specificity. Tag, class, id and compound selectors work, as do comma lists and descendant/child combinators; an inline style always wins. 

<style>
  h2 { color: #0f2f57; border-bottom: 0.6pt solid #c9d6e6; padding-bottom: 3pt; }
  .kpi { background-color: #eef4ff; border: 0.6pt solid #a9c0e0; padding: 6pt; }
  .kpi strong { color: #b23a2f; font-size: 15pt; }   /* descendant */
  section > h2 { letter-spacing: 0.3pt; }             /* child */
  #note { background-color: #fff6cc; padding: 5pt; }  /* id */
</style>

<p class="kpi"><strong>+18.4%</strong> revenue growth</p>
<p id="note"><mark>Highlighted</mark> text and a
  <span style="background-color:#dbeafe; opacity:0.9">tinted run</span>.</p>

<mark> paints the browser highlight #fff2a8 unless the element sets its own background. For styles shared across documents, pass a class map — it is applied after the stylesheet and before inline style: 

const report = htmlToReportDoc(html, {
  styles: {
    muted: { color: '#6b7c93', fontSize: 8.5 },
    kpi:   { backgroundColor: '#eef4ff', paddingTop: 6, paddingLeft: 6 },
  },
});

Pseudo-classes and attribute selectors are not supported; such rules are ignored. At-rules are skipped by the cascade, while @page and @font-face are handled by their own parsers.
