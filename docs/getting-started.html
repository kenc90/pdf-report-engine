Requirements

  • Node.js ≥ 18 — the package is ESM-only ("type": "module").
  • Runtime dependencies: pdfkit and fontkit. Everything else is a dev dependency.

Install

npm install kenc90/pdf-report-engine

Pin a tag, branch or commit with a # suffix:

npm install kenc90/pdf-report-engine#v0.1.0   # or #main, or #<sha>

Building from source:

npm install     # dev dependencies
npm run build   # compile TypeScript -> dist/ (JS + .d.ts)
After npm run build, the package's exports map points at dist/, so you can import { renderToBuffer } from 'pdf-report-engine' from any ESM project.

Your first report (IR)

The report is a plain data object — ReportDoc. It is serialisable, diffable and validatable without any parser.

import fs from 'node:fs';
import { renderToBuffer } from 'pdf-report-engine';

const report = {
  info: { title: 'Hello, PDF' },
  page: { size: 'a4', margin: 56 },
  style: { fontFamily: 'Helvetica', fontSize: 11, color: '#222' },
  body: [
    { type: 'heading', level: 1, content: 'Quarterly Snapshot', color: '#1a3d6d' },
    { type: 'paragraph', content: 'A vector PDF with selectable text — no browser involved.' },
  ],
};

const pdf = await renderToBuffer(report);
fs.writeFileSync('output/hello.pdf', pdf);

Without embedding fonts, the standard PDF base-14 fonts (like Helvetica) render out of the box, so a first report needs nothing installed.

Embedding fonts

To use real font programs (and non-Latin scripts), register them with readFontFiles. It reads from disk paths or from bytes you already have.

import { renderToBuffer, readFontFiles } from 'pdf-report-engine';

const fonts = await readFontFiles([
  { family: 'Arial', path: 'C:/Windows/Fonts/arial.ttf',  weight: 400 },
  { family: 'Arial', path: 'C:/Windows/Fonts/arialbd.ttf', weight: 700 },
]);

const pdf = await renderToBuffer(report, { fonts });
Prefer a graceful fallback: filter candidates with fs.existsSync() and pass fonts: [] when none are found — the base-14 fonts still render, so the report never hard-fails on a machine with no system fonts.
Per-glyph fallback. Within a run, any character the resolved face has no glyph for is re-resolved against the other registered faces (nearest weight/style) and painted in that font — so 陳大文 test in an Arial paragraph renders CJK via a registered CJK face and Latin via Arial, with no explicit font-family on the Chinese. The only requirement is that a covering font is registered (the CLI does this per platform; in the library add one via readFontFiles). It reaches only registered faces, keeping output deterministic.

Running in the browser

The core engine is pure JavaScript and bundles for the browser — the library graph has no top-level node:* imports. Two constraints remain: pdfkit itself needs Buffer/streams, so build with a Node-polyfill plugin (Vite: vite-plugin-node-polyfills; webpack: resolve.fallback); and a browser cannot read installed system fonts, so you either fetch the font bytes yourself (TTF/OTF/TTC) or just link a web font and let the engine resolve it — see Web fonts & Google Fonts.

import { renderToBuffer } from 'pdf-report-engine';

const font = async (url, family, weight) =>
  ({ family, weight, buffer: new Uint8Array(await (await fetch(url)).arrayBuffer()) });

const fonts = await Promise.all([
  font('/fonts/Inter-Regular.ttf', 'Inter', 400),
  font('/fonts/Inter-Bold.ttf',    'Inter', 700),
  font('/fonts/NotoSansSC.ttf',    'Microsoft YaHei'), // registered CJK face enables fallback
]);

const pdf = await renderToBuffer(report, { fonts });
const url = URL.createObjectURL(new Blob([pdf], { type: 'application/pdf' }));
In the browser: pass buffer bytes (never a path — that lazily pulls in node:fs/promises); give images as bytes, a data: URI, or an http(s) URL (a filesystem path has no intrinsic size here); and run large reports in a Web Worker so the UI thread is not blocked.

No-build: load from jsDelivr

If you don't want a bundler, the prebuilt ESM bundle is served from jsDelivr via GitHub. Pin a tag or commit SHA (not a branch) so the CDN cache stays immutable: 

<script type="module">
  import { htmlToReportDoc, renderToBuffer } from
    'https://cdn.jsdelivr.net/gh/kenc90/pdf-report-engine@main/docs/browser/pdf-report-engine.js';

  const report = htmlToReportDoc('<h1>Hello</h1>');
  const pdf = await renderToBuffer(report);
  const url = URL.createObjectURL(new Blob([pdf], { type: 'application/pdf' }));
  window.open(url);
</script>

jsDelivr also mirrors npm, so once the package is published you can switch to the shorter https://cdn.jsdelivr.net/npm/pdf-report-engine@latest/docs/browser/pdf-report-engine.js form. The wawoff2-decoder.js file sits alongside the bundle automatically — the engine loads it lazily only when it needs to decode WOFF2 (e.g. Google Fonts).

The bundle must be loaded as an ES module (type="module" or import()). A plain <script> tag has no import.meta.url, so the sibling decoder lookup will fail.

Web fonts & Google Fonts

You don't have to fetch bytes by hand. When the HTML references a web font, the engine resolves and embeds it during renderToBuffer — the same code runs in Node and in the browser. htmlToReportDoc collects Google Fonts <link>/@import and inline @font-face rules into report.fonts, and resolveRemoteFonts fetches the CSS, downloads every font file and registers it under its family name. Then just use font-family:

<link href="https://fonts.googleapis.com/css2?family=Roboto:wght@400;700&display=swap" rel="stylesheet">
<h1 style="font-family: 'Roboto'">Quarterly Report</h1>   <!-- embedded, selectable -->
Google serves fonts by User-Agent: Node's fetch is answered with TTF (embedded directly), a browser is answered with WOFF2 — which fontkit can't read, so it is decoded to TTF in-process via the optional wawoff2 WebAssembly module. Google's per-script unicode-range subsets each become a face, reached by the same per-glyph fallback used for CJK. Unreachable fonts are skipped by default so a flaky CDN never fails the render. 
import { htmlToReportDoc, renderToBuffer } from 'pdf-report-engine';

const report = await htmlToReportDoc(html);            // report.fonts filled from the links/@font-face
const pdf = await renderToBuffer(report, {
  resolveFonts: { onError: 'throw', timeoutMs: 8000 },  // strict + bounded (e.g. in CI)
});

Data-driven tables

Feed an array into dataSource; the detail template expands once per row, groups produce breaks and subtotal footers, and column headers repeat on every page the table spans (set repeatHeader: false to opt out).

const rows = [
  { region: 'North', product: 'Widget', qty: 12, amount: 2400 },
  { region: 'South', product: 'Gizmo',  qty:  3, amount:  990 },
  // ...
];

const report = {
  data: { rows },
  bands: {
    pageFooter: {
      style: { fontSize: 8, color: '#666' },
      blocks: [{ type: 'paragraph', align: 'right',
        content: ['Page ', { bind: '$page.number' }, ' of ', { bind: '$page.total' }] }],
    },
  },
  body: [{
    type: 'table',
    showGrid: true, striped: true, repeatHeader: true,
    dataSource: { bind: '$data.rows' },
    columns: [
      { key: 'region', grow: 1 }, { key: 'product', grow: 2 },
      { key: 'qty', width: 50, align: 'right' },
      { key: 'amount', width: 110, align: 'right' },
    ],
    headerRows: [{ kind: 'header', cells:
      ['Region', 'Product', 'Qty', 'Amount'].map(c => ({
        content: c, style: { fontWeight: 'bold', color: '#fff' }, backgroundColor: '#1a3d6d' })) }],
    groups: [{
      by: '$row.region',
      footer: [{ bind: "concat('Subtotal: ', money($group.amount_sum))" }],
      footerStyle: { fontWeight: 'bold', align: 'right' },
    }],
    detail: { cells: [
      { bind: 'region' }, { bind: 'product' }, { bind: 'qty' },
      { bind: 'amount', format: '#,##0.00' },
    ] },
  }],
};

Cells are not limited to text. Add blocks to a cell to stack any flow block inside it (an image, a barcode, a chart, a nested table, paragraphs). Rows grow to the measured stack height and remain atomic for pagination. Rows and cells also accept visible, styleWhen and colorScale: 

columns: [
  { key: 'name', grow: 1 },
  // Auto-ranged heatmap for the whole column.
  { key: 'score', width: 64, align: 'right',
    colorScale: { from: '#eef4ff', to: '#1e3a8a' } },
],
detail: {
  visible: { expr: '!$row.archived' },                       // row filter
  styleWhen: [{ when: '$row.score < 40',
                style: { backgroundColor: '#fff5f5' } }],   // row condition
  cells: [
    { blocks: [
      { type: 'paragraph', content: { bind: 'name' } },
      { type: 'barcode', symbology: 'qr', value: { bind: 'code' }, moduleSize: 1 },
    ] },
    {},                                                       // auto-binds the score
  ],
},

In HTML the same knobs are declarative: data-if filters a block, <tr> or <td>; data-when + data-when-style adds a conditional rule; data-color-scale shades a cell; and a <td> containing block children becomes a rich cell automatically. See samples/rich-cells.html, samples/conditional-format.html and samples/color-scale.html (the ramp on its own).

Breaks & keep-together

Pagination fills a vertical cursor down the page, one fragment at a time. A paragraph becomes one fragment per typeset line — that is why prose flows freely across pages — while a table row, an image, a chart, a barcode and a table-of-contents row are each a single fragment and therefore atomic: if they do not fit below, they move whole to the next page.

Forcing a break

{ type: 'pageBreak' }                                  // a block of its own
{ type: 'heading', level: 1, content: 'Annex', breakBefore: 'page' }
{ type: 'paragraph', content: 'End of part one', breakAfter: 'page' }

In HTML: <div style="page-break-before: always"> (or the modern break-before), and the same for page-break-after / break-after. A break is never taken twice: a forced break at the top of a page — including a pageBreak block that follows another break — is swallowed, and a breakAfter: 'page' on the last block does not add a blank page.

Keeping things together

GoalWhat to write
A heading must not sit alone at the foot of a page keepWithNext: true on the heading. It glues that block to the next one; the chain keeps going, so two consecutive keepWithNext blocks plus their shared follower move together.
A short paragraph, note or signature line must stay whole breakInside: 'avoid' on the block (in HTML, page-break-inside: avoid). Its lines are chained into one run.
A small table should not be cut in half breakInside: 'avoid' on the table block — every row then travels with every other row.
Column headers on every page of a long table Nothing: headerRows repeat automatically whenever the table continues on a new page. repeatHeader: false turns the repetition off; repeatHeader: true is the default written out.
A group header stuck to its first data row Automatic — group headers carry keepWithNext for you.
One group per page groups: [{ by: '$row.region', pageBreak: true }], optionally with resetPageNumber: true to restart {PAGE} from 1 on that page ($page.total still counts the whole document).

A keep-together chain is moved as a unit, and a chain taller than the page cannot be satisfied: it is placed anyway and overruns the bottom margin, exactly as a browser does with an oversized page-break-inside: avoid box. Keep the guarded content short.

groups[].by partitions consecutive rows, Jasper-style: the group ends whenever the value changes. Sort the data by the grouping key first — interleaved North, South, North, … input yields one group per row.

What pagination does not do

There are no widow/orphan controls (widows, orphans are accepted and ignored), and 'avoid' as a break value (breakBefore: 'avoid', breakAfter: 'avoid') does nothing — express that with keepWithNext on the block before instead. A group footer is the usual casualty: it can still be pushed onto the next page alone, since its only hint is advisory. Also note that {TOP} / $page.top (the height of the current page's content area) is never populated, and pageBreak blocks ignore always.

Looking at the result

createReport() returns the model before any PDF is written, so break behaviour is inspectable without a viewer: 

const { pages } = createReport(report, {});
pages.forEach((p, i) => console.log(i + 1, p.height, p.body.map((f) => f.fragment.height)));

Charts

A chart block draws bar, line, area, pie, donut, combo, waterfall, scatter, bubble, radar, gauge and heatmap charts with the same primitives as the rest of the engine: real vector marks and selectable labels, no canvas and no charting library. A chart is laid out as one atomic fragment, so it never splits across a page. 

body: [
  {
    type: 'chart', kind: 'bar', title: 'Revenue vs. cost ($M)', height: 170,
    categories: ['Q1', 'Q2', 'Q3', 'Q4'],
    series: [
      { name: 'Revenue', values: [12.4, 18.1, 15.2, 22.6] },
      { name: 'Cost',    values: [7.1, 9.4, 8.2, 11.3] },
    ],
    legend: 'bottom', showValues: true, valueAxis: { format: '#,##0.0' },
  },
  {
    // line: unlike bar/area, the value axis is not forced through zero.
    type: 'chart', kind: 'line', title: 'ARPU ($)', height: 160,
    categories: ['Jul', 'Aug', 'Sep', 'Oct'],
    series: [
      { name: 'Consumer',   values: [21.4, 22.0, 23.1, 24.3] },
      { name: 'Enterprise', values: [38.2, 39.6, 39.1, 43.0] },
    ],
    valueAxis: { min: 18, max: 48, ticks: 4, format: '$#,##0.0' },
  },
  {
    type: 'chart', kind: 'donut', title: 'Revenue mix', height: 150,
    categories: ['North', 'South', 'East', 'West'],
    series: [{ values: [42, 28, 18, 12] }],
    legend: 'right', innerRadius: 0.55,
  },
  {
    // pie is the same block without a hole; `stacked: true` piles bars or areas.
    type: 'chart', kind: 'pie', title: 'Channel mix', height: 150,
    categories: ['Direct', 'Partner', 'Retail', 'Online'],
    series: [{ values: [37, 25, 22, 16] }],
    legend: 'right',
  },
]

Three kinds add depth. A combo chart draws each series as a bar, line or area and can put a series on a secondary right axis; stacked: '100%' normalises every category to its own total; a waterfall turns one delta series into a running balance: 

// Bars on the left axis, a line on its own right axis.
{
  type: 'chart', kind: 'combo', title: 'Revenue and margin', height: 180,
  categories: ['Q1', 'Q2', 'Q3', 'Q4'],
  series: [
    { name: 'Revenue', values: [12, 18, 15, 22] },
    { name: 'Margin', values: [18, 19, 21, 24], type: 'line', axis: 'right' },
  ],
  rightAxis: { min: 0, max: 30, ticks: 5, format: '0"%"' },
  legend: 'bottom',
}

// 100% stacking: each category sums to 100, labels read as percentages.
{
  type: 'chart', kind: 'bar', stacked: '100%', title: 'Revenue mix', height: 160,
  categories: ['Q1', 'Q2', 'Q3'],
  series: [
    { name: 'Product', values: [60, 55, 50] },
    { name: 'Services', values: [40, 45, 50] },
  ],
  showValues: true,
}

// Waterfall: totals[0] seeds the opening balance, later totals close the bridge.
{
  type: 'chart', kind: 'waterfall', title: 'Cash bridge', height: 180,
  categories: ['Opening', 'Revenue', 'Costs', 'Closing'],
  series: [{ name: 'Cash', values: [80, 30, -20, 0] }],
  totals: [0, 3], showValues: true,
  waterfallColors: { increase: '#15803d', decrease: '#b91c1c', total: '#1e3a8a' },
}

values and categories accept literal arrays, CSV strings ('12,18,9') or bindings ('$data.revenue'), so a chart can be data-driven without a second source. bar/line/area read one value per category per series; pie/donut read series[0].values and label slices from categories (their legend shows each slice's percentage). Set stacked: true to stack bars or areas instead of grouping them, or stacked: '100%' to normalise each category to its own total. Combo series read type and axis; waterfall totals mark running-total bars (index 0 seeds the opening balance).

Bookmarks, table of contents & links

Every heading emits an outline entry — the bookmark tree PDF readers show in their sidebar. Entries nest by heading level automatically, and a heading on a later page still attaches under the chapter opened earlier. Any block with an id also becomes a named destination. 

const report = {
  body: [
    { type: 'heading', level: 1, id: 'intro', content: 'Introduction' },
    { type: 'toc', title: 'Contents', maxLevel: 2 },        // real page numbers + dot leaders
    { type: 'heading', level: 2, id: 'charts', content: 'Charts' },
    { type: 'paragraph', content: ['See the chart below.'] },
    // ...
    { type: 'paragraph', content: [
      'Read the ', { text: 'live report', link: 'https://example.com/report' },
      ' or jump to ', { text: 'the appendix', link: '#appendix' }, '.',
    ] },
    { type: 'heading', level: 2, id: 'appendix', content: 'Appendix' },
  ],
};

A toc block collects the document's headings (up to maxLevel, default 3) and shows their final page numbers with dot leaders. Because the TOC's own height changes pagination, the renderer runs a small fixed-point loop — lay out → paginate → rebuild the TOC — until the entries stop moving (at most four passes). Each row links to its heading when that heading has an id.

Links live on content spans: an absolute URL (https:, mailto:, tel:) becomes an external annotation, and #anchor jumps to any block carrying that id. In HTML just use <a href> — the adapter maps both forms: 

<h1 id="intro">Introduction</h1>
<div data-toc data-title="Contents" data-level="2"></div>
<p>Read the <a href="https://example.com/report">live report</a>
   or <a href="#appendix">jump to the appendix</a>.</p>
<h2 id="appendix">Appendix</h2>
TOC attributeDefault / meaning
data-titleHeading above the entries (literal text also works).
data-level / data-max-levelDeepest heading level included (default 3).
data-leaders, data-page-numbersDot leaders and page numbers (both default true).
data-indent, data-gapIndent per nesting level (12pt) and gap before page numbers (4pt).

Per-heading and document-wide control stays in the IR:

{ type: 'heading', level: 2, content: 'Note', outline: false }          // no bookmark
{ type: 'heading', level: 2, content: 'Scope', outline: { level: 1 } }    // re-level the entry
{ type: 'heading', level: 2, content: 'Scope',
  outline: { numbering: 'append' } }                                     // 1.1 Scope, 1.2 ...

const report = { outline: false, body: [...] };   // no bookmark tree; a toc block still works
Give a heading an id when you want TOC rows or #id links to target it. The bookmark entry itself does not require one.

Hyperlinks & internal links

Text wrapped in <a href> becomes a clickable link in the generated PDF. External URLs (https://…) open in the reader’s browser; internal anchors (#section-name) jump to the matching id within the document. 

<p>Visit <a href="https://github.com/kenc90/pdf-report-engine">the repository</a>.</p>
<p>Jump to <a href="#section-2">Section 2</a>.</p>
<h2 id="section-2">Section 2</h2>

Links are underlined and coloured automatically (via the style cascade). The engine registers named destinations for every heading id and draws link annotations at the correct glyph positions during the write pass.

No extra IR or API call is needed — the HTML adapter maps <a> to ContentSpan.link and the writer emits doc.link() / doc.goTo().

QR codes & barcodes

barcode blocks encode QR, Code 128 and EAN-13 as vector rectangles — no image is embedded, so codes stay crisp at any zoom. value is ordinary Content, so it can be a literal or a data binding. 

body: [
  { type: 'barcode', symbology: 'qr', value: 'https://example.com/reports/2026-Q3',
    moduleSize: 2.2, errorCorrection: 'Q' },
  { type: 'barcode', symbology: 'code128', value: 'RPT-2026-Q3-0042', height: 36 },
  { type: 'barcode', symbology: 'ean13', value: '590123412345' },   // checksum appended
]
<div data-barcode="qr" data-value="https://example.com/reports/2026-Q3"
     data-module-size="2.2" data-error-correction="Q"></div>
<div data-barcode="code128" data-value="RPT-2026-Q3-0042" data-color="#0f2f57"
     style="height:36pt"></div>
<div data-barcode="ean13" data-value="590123412345"></div>

Alignment follows the block's align (or HTML text-align). EAN-13 accepts 12 digits — the check digit is appended — or 13 digits, in which case the check digit is validated. Invalid values fail loudly at layout time.

Author with HTML

Prefer markup? The adapter parses a forgiving HTML/CSS subset into the same IR.

import { renderToBuffer, htmlToReportDoc } from 'pdf-report-engine';

const html = `
  <h1 style="color:#1a3d6d">Invoice #A-1001</h1>
  <table>
    <tr><th>Item</th><th>Price</th></tr>
    <tr><td>Widget</td><td>$19.00</td></tr>
  </table>`;

const report = htmlToReportDoc(html, { baseDir: process.cwd(), style: { fontFamily: 'Helvetica' } });
const pdf = await renderToBuffer(report);

The HTML subset understands colspan/rowspan, per-cell colours and borders, data-band for page headers/footers, and running {PAGE} tokens. A block-level <img> becomes an embedded image.

You can set the page from the document itself — no JS needed:

<style>
  @page { size: A4 landscape; margin: 15mm 18mm; }
</style>
<!-- or -->
<meta name="pdf-page" content="size=letter; margin=0.5in" />

Accepted: size = a named size (a3 a4 a5 b4 b5 letter legal tabloid executive), [w h] in any unit, plus portrait/landscape; margin = a CSS 1–4 value shorthand. A page passed to htmlToReportDoc(html, { page }) from JS overrides whatever the HTML declares.

Stylesheets, classes and highlights

A <style> element is parsed into a small but real cascade. Supported selectors are tag (h2), class (.kpi), id (#note) and compound combinations (p.kpi, #note strong), plus comma lists and descendant (whitespace) / child (>) combinators. Specificity follows CSS — id > class > tag — source order breaks ties, and an inline style always wins. 

<style>
  h2 { color: #0f2f57; border-bottom: 0.6pt solid #c9d6e6; padding-bottom: 3pt; }
  .kpi { background-color: #eef4ff; border: 0.6pt solid #a9c0e0; padding: 6pt; }
  .kpi strong { color: #b23a2f; font-size: 15pt; }   /* descendant */
  section > h2 { letter-spacing: 0.3pt; }             /* child */
  #note { background-color: #fff6cc; padding: 5pt; }  /* id */
</style>

<p class="kpi"><strong>+18.4%</strong> revenue growth</p>
<p id="note"><mark>Highlighted</mark> inline text and a
  <span style="background-color:#dbeafe; opacity:0.9">tinted run</span>.</p>

Runs carry their own background-color and opacity (0–1), so highlights and tinted emphasis are painted behind the glyphs. <mark> defaults to the browser highlight #fff2a8 unless the element sets a background. Block backgrounds paint the whole fragment; a background band plus opacity gives a translucent letterhead or watermark.

Pseudo-classes and attribute selectors (:hover, [data-x]) are not supported — they are ignored rather than approximated. At-rules such as @media are skipped by the cascade; @page and @font-face are handled by their own parsers. The same declarations can also be injected from JS with htmlToReportDoc(html, { styles: { muted: { color: '#6b7c93', fontSize: 8.5 } } }) — the class map sits between the stylesheet and inline style.

CSS box polish

A background box can be rounded, shadowed and filled with a linear gradient — authored straight from the HTML subset (border-radius, box-shadow, background: linear-gradient(…)) or set on the IR as borderRadius / boxShadow / backgroundImage. Everything stays vector: the rounding is a clipped bézier path, the gradient is painted as blended strips, the shadow as stacked translucent silhouettes — no rasterisation. 

<!-- A rounded, gradient banner with a soft drop shadow. -->
<div style="background: linear-gradient(to right, #1e3a8a, #38bdf8);
            color: #fff; border-radius: 8px; box-shadow: 2px 3px 6px rgba(15,47,87,0.35);
            padding: 10pt 12pt;">
  Quarterly results are in.
</div>

<!-- A plain rounded callout (background fill only). -->
<p style="background-color: #eef4ff; border-radius: 10px; padding: 9pt 11pt;">
  A tinted, rounded note box.
</p>
// IR: the same decorations are ordinary box properties.
{
  type: 'paragraph',
  content: 'Card',
  backgroundColor: '#ffffff',
  backgroundImage: { direction: 'to bottom', from: '#f8fafc', to: '#c7d2fe' },
  borderRadius: 12,                               // number or [tl, tr, br, bl]
  boxShadow: { offsetX: 2, offsetY: 3, blur: 6, color: '#0f2f57', opacity: 0.3 },
}

A raster <img> is clipped to its rounded corners and can carry a shadow too. These are the honest limits of the first pass:

  • Fills round; borders do not. border-radius curves the background box (and clips an image); a straight border line is never curved.
  • Two-stop, cardinal gradients. Direction is to top/right/bottom/left or an angle (e.g. 45deg), snapped to the nearest of the four axes; only the first and last colour are modelled. A wrapping box samples the ramp against its whole height, so the gradient stays continuous across lines.
  • Shadow is approximate. blur is faked with layered fills; inset and a spread radius are ignored.
  • Outer-edge rounding only. On a box that wraps to several lines, only the top corners of the first line and the bottom corners of the last round; interior junctions stay square.

See it together in samples/box-polish.html.

Images (offline & online)

An ImageBlock takes a local path, a data: URI, raw bytes, or an http(s) URL. Offline sources render synchronously; remote URLs are fetched by renderToBuffer's pre-pass.

import fs from 'node:fs';

const report = {
  body: [
    { type: 'image', src: 'assets/logo.png', width: 200, align: 'center' },     // local path
    { type: 'image', src: fs.readFileSync('chart.png') },                        // raw bytes
    { type: 'image', src: 'https://cdn.example.com/chart.png', width: 300 },     // online
  ],
};

const pdf = await renderToBuffer(report, {
  images: { timeoutMs: 10000, maxBytes: 5000000, onError: 'skip' },
});

SVG vector images

An svg block draws an SVG document as real PDF paths — no rasterisation, no canvas, no resolution ceiling. Inline <svg> markup, data:image/svg+xml URIs, .svg file paths, raw bytes and remote http(s) URLs all take the same code path; the image pre-pass fetches remote sources before layout. 

import { renderToBuffer } from 'pdf-report-engine';

const report = {
  body: [
    // Inline markup.
    { type: 'svg', width: 48, src:
      '<svg viewBox="0 0 24 24"><path d="M4 4h16v16H4z" fill="#1e3a8a"/></svg>' },
    // A file on disk (resolved relative to `baseDir` at render time).
    { type: 'svg', src: 'assets/logo.svg', width: 120, align: 'center' },
    // A remote icon — fetched by the same pre-pass that resolves raster images.
    { type: 'svg', src: 'https://cdn.example.com/icons/check.svg', width: 20 },
  ],
};
const pdf = await renderToBuffer(report);

In HTML the same block appears either inline or via an <img>:

<svg viewBox="0 0 24 24" width="24" height="24">
  <circle cx="12" cy="12" r="10" fill="#1e3a8a"/>
  <path d="M8 12h8M12 8v8" stroke="white" stroke-width="2"/>
</svg>

<img src="assets/logo.svg" width="140" alt="logo">    <!-- same .svg route -->

Supported subset:

  • Shapes — path (all commands, including A arcs, flattened to polylines), rect with rx/ry, circle, ellipse, line, polyline, polygon, and nested g groups.
  • Paint — fill, stroke (colour or none), fill-opacity, stroke-opacity, opacity, stroke-width, stroke-dasharray, stroke-linecap, stroke-linejoin, and fill-rule="evenodd" so a shape with a subpath inside it renders the hole (used by donuts, glyphs, icons).
  • Transforms — translate, scale, rotate, skewX/skewY and matrix, plus a top-level viewBox / preserveAspectRatio. Presentation attributes and inline style are both honoured.
  • Unsupported — filters, gradients, patterns, nested image elements and text are ignored rather than approximated; convert those to paths in your editor first.
Sizing follows the intrinsic rules of an image: give an explicit width (or height) in points and the other dimension follows the aspect ratio; omit both and the SVG's viewBox gives its intrinsic size (converted at 96 dpi, so 1 px = 0.75 pt), capped to the content width.

Flexbox layout

A display: flex container lays out any flow blocks along a row or a column. The engine implements a pragmatic CSS-flexbox subset: main-axis direction, optional wrap, justify-content, align-items / align-self, gap and per-item flex-grow / flex-shrink / flex-basis. A flex container is measured as one atomic fragment, so it never splits across pages — nest a flex inside another to build a two-dimensional layout (row of columns, or column of rows). 

// IR: a KPI strip that distributes three cards evenly.
{
  type: 'flex',
  direction: 'row',
  justify: 'space-between',
  alignItems: 'center',
  gap: 12,
  children: [
    { block: { type: 'paragraph', content: 'Revenue ↑' }, grow: 1 },
    { block: { type: 'paragraph', content: 'Cost ↓' },   grow: 1 },
    { block: { type: 'paragraph', content: 'Margin ↑' }, grow: 1 },
  ],
}
<!-- HTML: the same row via CSS. -->
<div style="display:flex; justify-content:space-between; align-items:center; gap:12pt">
  <div style="flex:1 1 auto">Revenue ↑</div>
  <div style="flex:1 1 auto">Cost ↓</div>
  <div style="flex:1 1 auto">Margin ↑</div>
</div>

<!-- Wrapping row of chips with a per-item align-self override. -->
<div style="display:flex; flex-wrap:wrap; gap:6pt 10pt">
  <span class="chip">alpha</span>
  <span class="chip" style="align-self:flex-end">tall</span>
  <span class="chip">gamma</span>
</div>

Rich inline text

Per-run style overrides within a paragraph are fully supported: bold, italic, underline, strikethrough, colour, font-size, background highlight, and opacity — all via inline HTML elements or style attributes. 

<p>
  Normal <strong>bold</strong> <em>italic</em> <u>underline</u>
  <mark>highlight</mark>
  <span style="color:#dc2626">red</span>
  <span style="text-decoration:line-through">strikethrough</span>
  <span style="font-weight:bold; font-style:italic">bold-italic</span>
</p>

Each styled span becomes an InlineSource with a sparse StyleProps override, typeset independently so the glyph positions, font switches, and decorations (underline / line-through) are drawn precisely.

Page watermark

A declarative watermark is rendered diagonally across every page as filled vector glyph outlines (not PDF text operators), so it cannot be selected or extracted by text search. Add it via <meta name="watermark"> in HTML, or the watermark field on the ReportDoc IR. By default it sits behind the body; set layer: 'foreground' to paint it on top of everything on the page. 

<!-- HTML -->
<meta name="watermark" content="DRAFT" data-watermark-rotate="-35" data-watermark-opacity="0.18" data-watermark-layer="foreground" />

<!-- or on  -->
<body data-watermark="CONFIDENTIAL" data-watermark-layer="foreground">
// IR
{
  watermark: { text: 'DRAFT', rotate: -35, fontSize: 72, color: '#c0c0c0', opacity: 0.18, layer: 'foreground' },
  body: [ … ]
}
PropertyDefaultDescription
text—The watermark string.
rotate-35Degrees counter-clockwise.
fontSize72Text size in pt.
color#c0c0c0Fill colour of the glyph outlines.
opacity0.18Paint opacity (0–1).

The watermark is generated in the pagination pass as a page-spanning fragment of path DrawCommands (one subpath per closed glyph contour). The writer applies the rotation transform around the page center and paints the fragment either first (background layer) or last (foreground layer) in the per-page draw order.

Multi-column layout

Distribute child blocks across N equal-width columns using CSS column-count or the data-columns attribute. The engine sequentially fills columns by height (total / count). 

<div style="column-count: 2; column-gap: 14pt">
  <p>First paragraph flows into column 1.</p>
  <p>This may continue into column 2.</p>
</div>

<!-- Or via data attribute with a vertical rule -->
<div data-columns="3" data-column-gap="10pt" data-column-rule="#cbd5e1">
  <p>…</p>
</div>
// IR
{
  type: 'columns',
  count: 2,
  gap: 14,
  rule: { color: '#cbd5e1', width: 0.5 },
  children: [
    { type: 'paragraph', content: 'Left' },
    { type: 'paragraph', content: 'Right' },
  ],
}

The ColumnBlock is kept atomic (never splits across pages). Vertical rules are optional lines drawn at column boundaries.

Streaming output

renderToStream() returns a ReadableStream<Uint8Array> that flushes each page incrementally, reducing peak memory for server-side rendering. 

import { renderToStream } from 'pdf-report-engine';

const stream = await renderToStream(report, { fonts: fontSources });

// Node: pipe to a response
stream.pipeTo(Writable.toWeb(response.body));

// Or collect chunks manually
const reader = stream.getReader();
while (true) {
  const { done, value } = await reader.read();
  if (done) break;
  response.write(value);
}

Internally this sets bufferPages: false, which tells pdfkit to flush each page’s encoded stream as soon as the next page starts — the ideal mode for HTTP streaming.

Encryption & permissions

Set encrypt on the ReportDoc to write a password-protected PDF through pdfkit's standard security handler (RC4 128-bit). A userPassword gates opening the file; an ownerPassword gates changing permissions (one is generated if you omit it). At least one password must be present — otherwise the document is written unencrypted, byte-for-byte as before. 

const report = {
  info: { title: 'Payroll — confidential' },
  encrypt: {
    userPassword: 'reader-opens-with-this',   // required to open
    ownerPassword: 'owner-can-change-this',   // required to lift restrictions
    permissions: {
      printing: true,
      copying: false,          // block text/graphics extraction
      modifying: false,
      annotating: false,
      fillingForms: false,
      contentAccessibility: true,   // allow screen readers
      documentAssembly: false,
    },
  },
  body: [ /* … */ ],
};

const pdf = await renderToBuffer(report);   // the bytes are encrypted on write
PermissionGrants (when true)
printingPrint the document.
modifyingEdit the document beyond form filling and annotations.
copyingCopy text and graphics.
annotatingAdd or change comments and form fields.
fillingFormsFill in existing interactive forms.
contentAccessibilityEnable screen readers / text extraction for accessibility.
documentAssemblyAssemble the document (insert, rotate, delete pages; add bookmarks).
Every flag defaults to permitted when omitted. PDF enforces the permissions against the owner password, which pdfkit supplies automatically when you leave ownerPassword out — so they take effect as long as any password is present. This is viewer-enforced RC4 security: treat the flags as a usage hint, not durable protection, while a userPassword genuinely gates opening.

The CLI

Convert authoring HTML files to PDF, or build the bundled demo report.

# HTML -> PDF (relative image paths resolve against the HTML file's folder)
npx tsx src/cli/html-to-pdf.ts samples/annual-report.html -o output/

# The formal testimonial — works out of the box: fonts are auto-detected for your
# platform (Arial / Georgia / Times New Roman + a CJK face), no flags needed:
npx tsx src/cli/html-to-pdf.ts samples/testimonial.html -o output/testimonial.pdf

# Override / add a specific font with -f/--font (repeatable). These ADD to the
# auto-detected fonts, so the CJK face stays available even when you specify your own:
npx tsx src/cli/html-to-pdf.ts samples/testimonial.html \
  -f "Times New Roman=/usr/share/fonts/truetype/liberation/LiberationSerif-Regular.ttf:400"

# Pick a face inside a TrueType collection (.ttc) with a `#PostScriptName`:
npx tsx src/cli/html-to-pdf.ts samples/testimonial.html \
  -f "PMingLiU=C:/Windows/Fonts/mingliu.ttc#PMingLiU"

# Build the sample multi-page report -> output/demo.pdf
npm run demo
FlagMeaning
<input…>One or more HTML files and/or directories. A directory contributes its top-level *.html/*.htm. Each input is written as a same-named .pdf.
-o, --out <path>Output location. A directory (or no -o) keeps each input's base name; a .pdf path is used verbatim, but only for a single input. Parent directories are created.
-d, --data <file>JSON file whose object becomes the report data root for data-each/data-bind. If omitted, an adjacent <name>.data.json is auto-paired when present (so directory runs populate bound tables).
-f, --font <spec>Register an embeddable font; repeatable. Accepts <path> (family inferred from the filename) or <family>=<path>[:weight], and for a TrueType collection append #<PostScriptName> to pick a face (e.g. mingliu.ttc#PMingLiU). --page <pt>Base font size in points for the document (default 11) — not the page size. Must be a positive number.

By default the CLI auto-detects fonts per platform — Windows (C:/Windows/Fonts), macOS (/System/Library/Fonts/Supplemental), and Linux (via fontconfig fc-match/fc-list, falling back to scanning common font dirs) — registering Arial / Georgia / Times New Roman plus a CJK-capable face. Explicit -f fonts are merged with those, so adding a family does not drop CJK support. Use --no-auto-fonts to load only your -f fonts. If nothing is found, output uses the base-14 fonts (Latin-1 only — CJK will not render). Note that Georgia uses old-style figures (digits of mixed height); choose a lining-figure font such as Times New Roman or Arial if numerals must align with capitals.

Multiple inputs are processed independently: each file is converted in its own try/catch, so one broken input is reported as FAILED … and the rest still render. Any failure leaves a non-zero exit code, and relative image paths resolve against each HTML file's own folder.
