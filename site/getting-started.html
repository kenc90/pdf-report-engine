Requirements

  • Node.js ≥ 18 — the package is ESM-only ("type": "module").
  • Runtime dependencies: pdfkit and fontkit. Everything else is a dev dependency.

Install

npm install pdf-report-engine

Building from source:

npm install     # dev dependencies
npm run build   # compile TypeScript -> dist/ (JS + .d.ts)
After npm run build, the package's exports map points at dist/, so you can import { renderToBuffer } from 'pdf-report-engine' from any ESM project.

Your first report (IR)

The report is a plain data object — ReportDoc. It is serialisable, diffable and validatable without any parser.

import fs from 'node:fs';
import { renderToBuffer } from 'pdf-report-engine';

const report = {
  info: { title: 'Hello, PDF' },
  page: { size: 'a4', margin: 56 },
  style: { fontFamily: 'Helvetica', fontSize: 11, color: '#222' },
  body: [
    { type: 'heading', level: 1, content: 'Quarterly Snapshot', color: '#1a3d6d' },
    { type: 'paragraph', content: 'A vector PDF with selectable text — no browser involved.' },
  ],
};

const pdf = await renderToBuffer(report);
fs.writeFileSync('output/hello.pdf', pdf);

Without embedding fonts, the standard PDF base-14 fonts (like Helvetica) render out of the box, so a first report needs nothing installed.

Embedding fonts

To use real font programs (and non-Latin scripts), register them with readFontFiles. It reads from disk paths or from bytes you already have.

import { renderToBuffer, readFontFiles } from 'pdf-report-engine';

const fonts = await readFontFiles([
  { family: 'Arial', path: 'C:/Windows/Fonts/arial.ttf',  weight: 400 },
  { family: 'Arial', path: 'C:/Windows/Fonts/arialbd.ttf', weight: 700 },
]);

const pdf = await renderToBuffer(report, { fonts });
Prefer a graceful fallback: filter candidates with fs.existsSync() and pass fonts: [] when none are found — the base-14 fonts still render, so the report never hard-fails on a machine with no system fonts.

Data-driven tables

Feed an array into dataSource; the detail template expands once per row, groups produce breaks and subtotal footers, and repeatHeader keeps column headers on every page.

const rows = [
  { region: 'North', product: 'Widget', qty: 12, amount: 2400 },
  { region: 'South', product: 'Gizmo',  qty:  3, amount:  990 },
  // ...
];

const report = {
  data: { rows },
  bands: {
    pageFooter: {
      style: { fontSize: 8, color: '#666' },
      blocks: [{ type: 'paragraph', align: 'right',
        content: ['Page ', { bind: '$page.number' }, ' of ', { bind: '$page.total' }] }],
    },
  },
  body: [{
    type: 'table',
    showGrid: true, striped: true, repeatHeader: true,
    dataSource: { bind: '$data.rows' },
    columns: [
      { key: 'region', grow: 1 }, { key: 'product', grow: 2 },
      { key: 'qty', width: 50, align: 'right' },
      { key: 'amount', width: 110, align: 'right' },
    ],
    headerRows: [{ kind: 'header', cells:
      ['Region', 'Product', 'Qty', 'Amount'].map(c => ({
        content: c, style: { fontWeight: 'bold', color: '#fff' }, backgroundColor: '#1a3d6d' })) }],
    groups: [{
      by: '$row.region',
      footer: [{ bind: "concat('Subtotal: ', money($group.amount_sum))" }],
      footerStyle: { fontWeight: 'bold', align: 'right' },
    }],
    detail: { cells: [
      { bind: 'region' }, { bind: 'product' }, { bind: 'qty' },
      { bind: 'amount', format: '#,##0.00' },
    ] },
  }],
};

Author with HTML

Prefer markup? The adapter parses a forgiving HTML/CSS subset into the same IR.

import { renderToBuffer, htmlToReportDoc } from 'pdf-report-engine';

const html = `
  <h1 style="color:#1a3d6d">Invoice #A-1001</h1>
  <table>
    <tr><th>Item</th><th>Price</th></tr>
    <tr><td>Widget</td><td>$19.00</td></tr>
  </table>`;

const report = htmlToReportDoc(html, { baseDir: process.cwd(), style: { fontFamily: 'Helvetica' } });
const pdf = await renderToBuffer(report);

The HTML subset understands colspan/rowspan, per-cell colours and borders, data-band for page headers/footers, and running {PAGE} tokens. A block-level <img> becomes an embedded image.

Images (offline & online)

An ImageBlock takes a local path, a data: URI, raw bytes, or an http(s) URL. Offline sources render synchronously; remote URLs are fetched by renderToBuffer's pre-pass.

import fs from 'node:fs';

const report = {
  body: [
    { type: 'image', src: 'assets/logo.png', width: 200, align: 'center' },     // local path
    { type: 'image', src: fs.readFileSync('chart.png') },                        // raw bytes
    { type: 'image', src: 'https://cdn.example.com/chart.png', width: 300 },     // online
  ],
};

const pdf = await renderToBuffer(report, {
  images: { timeoutMs: 10000, maxBytes: 5000000, onError: 'skip' },
});

The CLI

Convert authoring HTML files to PDF, or build the bundled demo report.

# HTML -> PDF (relative image paths resolve against the HTML file's folder)
npx tsx src/cli/html-to-pdf.ts samples/annual-report.html -o output/

# Build the sample multi-page report -> output/demo.pdf
npm run demo

Then explore the runnable library scripts in the Examples page, or read the full surface on the API reference.
